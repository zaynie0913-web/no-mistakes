## Stage 1 · 数据层 + 最简录入

### 一、数据命名空间

新增 `D.mockExam`,建议结构:

```js
D.mockExam = {
  version: 1,
  records: [],     // 每一次训练是一条独立记录,历史不可变,不允许后续修改内容
  metadata: {},     // Stage 1 留空对象即可,为将来的难度库预留,不要现在填任何数据
  settings: {}      // Stage 1 大概率用不到,如果确实不需要可以不设,不要为了"预留"硬造字段
}
```

具体字段命名如果和现有项目风格(驼峰/下划线、缩写习惯)有出入,以现有项目规范为准,
不用照抄这里的名字。

**旧存档没有 `D.mockExam` 时**,`load()` 和导入两处都要给默认值,**规则必须完全一致**——
这是 v19 出过真实事故的地方(当时是别的字段,两处规则不对称导致导入半途崩溃),不要重蹈。

### 二、Stage 1 考试范围

英语一,2015–2026,题型:整套 / 完形 / 阅读 / 新题型 / 翻译 / 小作文 / 大作文
政治一,2015–2026,题型:整套 / 单选 / 多选 / 分析题

政治是全国统考,不存在"北京政治一独立试卷"。「报考地区:北京」这次不做任何算法,
如果 Stage 1 需要用户设置里已经有这个字段就留着不动,没有就不新增。

### 三、最小记录流程

路径:今天 tab → 真题训练入口(折叠,复用 kyBar 模式)→ 英语一/政治一 → 年份 → 题型 → 记录。

记录时**最少只需要**:年份、题型。然后二选一:开始计时→完成,或手动输入用时。
得分可填可不填,**不允许设成必填**。

**Stage 1 严禁出现**:强制填分数、强制填错因、强制填难度、强制填备注。
这些不是"以后再加",是这一阶段的验收红线,出现任何一个都算没做对。

### 四、刷次自动计算

用户不填刷次,系统算。算法:

```
attempt = records.filter(r => r.subject===当前科目 && r.year===当前年份 && r.scope===当前题型).length + 1
```

**底层永远保存每一条真实记录**,不要只存一个累计数字——不然以后想看训练历史就没有数据了。
「刷次」只是显示层从记录数量算出来的结果。

### 五、真题时长并入现有统计(本阶段核心,做错了整个 Stage 1 就是失败的)

`todayMins()` 和 `subjLastSeen()` 都要能看到真题记录产生的时长,**不建 `mockTodayMins()`
`mockStudyStats()` 这类第二套函数**。

方向(不是代码,细节判断交给你结合实际代码结构决定):给这两个函数各加一个新的数据源分支,
读 `D.mockExam.records` 里日期匹配当天的记录(日期用 Stage 1 里记录时就该按 `dkey(studyNow())`
写死在记录上的那个字段判断,不要在统计时临时用时间戳反推,避免和 `DAYCUT` 换算的口径不一致)。
`subjLastSeen()` 那边,真题记录对应的 `subject` 归到「真题」这个既有分类下
(`SUBJECTS_BUILTIN` 已经有了,直接用)。

改这两个函数时,按第十五条要求写清楚"为什么必须改""改了什么""有没有影响旧数据",
写进最后的报告里,不要只说"改好了"。

### 六、避免重复计算 —— 判据说明

**系统自己产生的时长只能被算一次**:一条真题记录,不管时长来自"计时"还是"手动输入",
都只在 `todayMins()` 里被这一条记录贡献一次,不存在"同一条记录被两套逻辑各算一遍"的路径。

**但有一种情况现有系统管不了,也不该试图去管**:用户用真题模块记了"阅读 67 分钟",
又手滑在加码梯里手动加了一条"英语阅读 67 分钟"——这是用户发起的两个独立操作,
不是系统重复计算,系统没有能力也不应该去猜"这两条是不是在说同一件事"并自动去重。
**这一阶段不需要为这种情况写任何防重复逻辑**,只需要保证"系统自己那条数据链路"
(计时/手动输入 → 一条 record → 一次时长贡献)不出现内部重复即可。

### 七、首页入口

「今天」tab 里加一个轻量入口,折叠模式照抄 `kyBar`/`kyToggle`/`kyList` 那一套,
不要复制大量代码——抄的是交互模式和 CSS 类命名习惯,不是把 `renderKy()` 整个复制粘贴改名。
展开后只需要「英语一」「政治一」两个入口,再往下点才进年份/题型选择。

### 八、Stage 1 严禁做的事

难度数据库 / 历年平均分 / 多机构难度综合 / 智能时间建议 / AI 分析 / 下一步建议 /
错因分析 / 复杂统计图 / 排行榜 / 徽章 / streak / 在线 API / 网络依赖 / 真题题目内容 /
在线解析 / OCR / 作文批改。这些全部留到后续阶段,**尤其不要为了"提前准备"而偷偷实现
半套难度算法**——哪怕只是留一个空的难度字段占位都可以,但不要写任何判断逻辑。

### 九、为后续难度系统预留字段,但不填数据

记录结构里可以预留 `difficultySnapshot` / `difficultyConfidence` / `difficultySourceType`

这样的假数据占位,更不要为了让字段"看起来有内容"就随便填。宁可为空。

### 十、历史不可变

每条记录保存时固化:年份、科目、题型、刷次(存计算出来的那个值,不是公式)、日期、用时、

(参照 `d.set`/`d.pset`/`d.sset` 当日快照的做法——那套机制存在的意义就是"以后改了默认清单,
