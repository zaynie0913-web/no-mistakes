## 这是什么

一位跨专业考研学生(报考北师大文学院中国语言文学,2027 考研 / 2026 年 12 月初试)自用的
**单文件 HTML 打卡工具**。当前 `dakav22_2.html`,约 282 KB,HTML + CSS + JS 全在一个文件。

运行环境:**安卓「夸克浏览器」为主**(文件管理器打开本地文件 + 桌面快捷方式),iPad 为辅。
**不是 Chrome —— 所有真机判断按夸克来。** 夸克是 Blink 内核,但外壳行为和 Chrome 有差别,
至少这三点会影响 UI 验收:

- **有效可视高度比视口小一百多像素**(顶部地址栏 + 底部工具栏)。360×780 看着没问题的东西,
  在 360×520 的实际可用区里可能根本不在首屏。首屏判断一律按 **360×520** 量。
- **自带「网页字体大小」设置**,会整体放大字号。改动涉及按钮排布时,
  至少要在 **100% 和 125%** 两档各量一次,确认不横向溢出、文字不被按钮截断。
- **自带夜间 / 护眼模式,会强制反色**,可能和 v18 的 23 点自动切换叠成双重反色。
  页面已在 v21.1 声明 `<meta name="color-scheme" content="light dark">` 加
  `:root{color-scheme:light dark}` / `body{color-scheme:light}` / `body.dark{color-scheme:dark}`,
  这能挡住 Blink 自己的 Auto Dark Theme;但**挡不住浏览器外壳级的强制反色滤镜**
  (那是在渲染结果上做反相,页面声明什么都没用),这种只能让用户在夸克里关掉护眼模式。

没有服务端,没有构建步骤,没有网络请求。数据全部在 `localStorage`。

**`file://` 的存储边界(每版换文件名,这条要记牢)**:Chromium 内核下所有 `file://` 页面
共用同一个 origin(实测 `location.origin === "file://"`),所以 `dakav21.html` →
`dakav21_1.html` **换文件名不会丢数据**,新文件打开就能读到旧存档(已实测验证)。
但如果安卓文件管理器把文件以 `content://` 而不是 `file://` 交给浏览器,origin 就变了,
那种情况下数据读不到。**因此每次换版本文件之前,先让用户导出一份备份**,这是零成本的保险。

## 硬规则(违反会造成真实损失)

1. **不要重构、不要引入构建工具、不要拆分文件、不要加依赖。** 单文件是产品决策,不是技术债。
2. **不要为了让测试通过而修改产品代码。** 失败先分类(见下)再处理。
3. **Python 字符串替换前必须 `assert s.count(old) == 1`。**
   曾因 `replace('', x)` 把 97 KB 撑到 137 MB。
4. **改动前先复制工作副本**,不直接改交付版本。
5. **每次交付换文件名 + 版本号 +1**。同名文件在手机上会被缓存,用户会拿到旧版还以为手机坏了。
   **中文文件名在她手机上曾导致下载失败**,如果这次交付也是给用户下载,优先用纯英文文件名
   (如 `dakav20.html`),或者两种都给。
6. **文案禁用词**:必须、应该、赶紧、别偷懒、不许、否则、浪费。
   **不用 emoji;颜文字可以**(用户明确同意,如 `( ･ω･)b`)。
7. **不要擅自扩功能。** 只做 `TASKS.md` 里派给你的事。
8. **任何「点了没反应」都是 P0,哪怕它在逻辑上是对的。**
   v22 自查时撞到一个自己写的:计时进行中点「保存」,代码是 `if(!mockRun())mkSaveAll()`,
   意图是「计时中别误存」,实现出来却是**静默吞掉** —— 点下去零反应。
   对一个启动困难的用户,零反应等于「工具坏了」,她不会 debug,她会关掉。
   而且这个判断还把「计时挂在一个已经不在本屏的题型上」变成了死锁。
   **守则:任何按钮在任何状态下点下去,要么发生事情,要么给一句话。不允许第三种。**
9. **读代码得出的结论必须实测。** 这个项目里「只读不跑」已经错过多次
   (转盘 `slice(0,10)`、感受统计双记、TW 跨周、justRecovering 误判新用户)。
   搭最小环境跑一遍再下结论。
10. **UI 验收要真渲染、真量像素,不允许估算。** 这个容器里 **Chromium + Playwright 是可用的**
   (`/opt/pw-browsers/chromium`,playwright 在 `/opt/node22/lib/node_modules/playwright`,
   直接 `require` 绝对路径即可,不要跑 `playwright install`)。
   涉及排版、换行、点击区、字号的改动,一律用它在 **320 / 360 / 412** 三个宽度渲染并量出
   实际 `getBoundingClientRect()`,首屏判断按夸克的 **360×520** 有效高度量。
   v21 交付时曾写过「容器里没有浏览器,量不出像素」——**那句话是错的**,不要再犯。

## 产品前提(评审和实现都以此为准)

**用户的障碍是「开始」,不是「坚持」。** 整个产品建立在「允许失败、降低启动成本」上,**明确拒绝**:

- 连续打卡中断惩罚 / 断签清零 / 掉血 / 枯萎的树
- 排行榜、与他人比较
- 推送、锁机、强制提醒
- 任何用羞耻感或损失厌恶驱动的机制

如果你的结论是「缺少连续激励机制」「应该加提醒推送」「streak 断了没惩罚」,**那是把产品理解反了**。

其他不可动摇的约定:

- **允许中断,但禁止补记学习记录** —— 补记会让数据失真。
  但**健康类记录允许补记**(起床睡觉时刻、补剂漏记原因、饮品糖冰),因为那是客观事实不是自我评价。
- **统计口径一律按天去重**,不按次累加。
- 任何相关性展示必须带样本量门槛和免责说明,**不允许出现因果措辞**,**不算相关系数**。
- **不硬编码任何医学内容。** 观察框挂在具体某项补剂上,内容由用户自己写。
- **不做会隐藏或锁定内容的自适应状态机。** v20 的断档恢复机制(`justRecovering`)是
  一个反面教材的正面案例:一开始有人可能会想"状态不好就自动收窄显示范围",
  但这里刻意没有那么做 —— 三档任何时候都完整展示,只在需要时加一句安抚文案,
  不隐藏、不锁定、不持久化任何"降级"状态。以后任何类似需求,优先考虑这种轻量方案。

## 关键实现约定

- **学习日分界是凌晨 4 点**(`DAYCUT=4`),不是 0 点。拼日期键必须走 `studyNow()` / `dkey()`,
  **不要直接 `new Date()`**。例外:夜间模式判断故意用真实时钟。
- **周口径**用 ISO 周(`wkey()`),周一为首。`TW` 是 `let`,`refreshDay()` 里跟着刷新。
- **历史记录用当日快照判定**(`d.set` / `d.pset` / `d.sset`),清单以后改了旧记录不会退色。
  但「今天」的快照每次 render 会刷新成当前清单 —— 这是有意的,今天还没结束。
- **导入是两阶段提交**:所有合并落在暂存区 `T`,全部走完没抛错才 `D=T`。
  有静态守卫扫描导入函数体,出现直接写 `D.xxx` 的行就报错。加新字段要加在 `T` 上。
- **存档解析失败会冻结写入**:`LOAD_BROKEN` 非空时 `save()` 直接返回,
  页面显示处置台(导出原文 / 导入备份 / 放弃重来)。**不要绕过这个冻结。**

### v20:三档结构与轮换指针(本轮新增,重点读)

以前是「最低目标 / 加码梯」二元结构。v20 改成三档:

```
最低线(min)  ——  必须做,做完才算达标
标准线(std)  ——  v20 新增。「正常状态就该做」的量,不算加码但也不是硬性必须
加码梯(plus) ——  状态好才做,奖励性质
```

**古今轮换**:古代汉语和现代汉语以前同时摆在最低线,容易偏科(真实数据:现代汉语投入 0 分钟,
但真题命中率全卷最高)。v20 起每天只留一门站最低线,另一门整节课挪去标准线补。

```
GX_SUBJECTS = { gh: {...古代汉语模板...}, xh: {...现代汉语模板...} }
D.rotGX      当前谁站最低线,"gh" 或 "xh"
D.rotGXDate  上次翻页时的 TODAY 值
gxRotate()   在 refreshDay() 里被调用,只在「日期真正翻篇」那一刻拨一格 ——
             和 TW 跨周刷新是同一个模式,断更几天回来也只拨一格,不补、不追溯
gxRotateActive()  如果用户已经自定义过 D.minList(编辑过最低目标清单),
                  轮换不介入,回退到她自己编辑的静态清单
minDefaultToday()  没有自定义清单时,minAll() 返回 [背单词, 今天轮到的那门]
stdToday()   今天的标准线清单 = 默写复盘(常驻) + 轮换让路的那门(如果轮换生效)
```

**数据字段**:`d.std[k]`(勾选,和 `d.min` 同构)、`d.sset`(当日标准线快照,和 `d.set` 同构)。

### v22.2:撤销的边界(以后不得越过这条线)

`bid`(批次号)+ `D.mockExam.undo` 只服务一件事:**取消一次刚刚发生的误操作**。
它**不是编辑历史的入口**,以后不得援引这一条去做任何「修改已有记录」的功能。

三条硬约束:

- **只针对最新一批,且没跨学习日。** 又存了新的一批、跨了学习日(用 `dkey(studyNow())` 判,
  不是自然日)、或者她自己点掉,入口就消失。
- **只能整批撤,不能挑一条撤。** 挑着撤就是在改写历史。
- **撤销 = 整条删除**,不留痕迹、不产生「已撤销」记录、**不重算任何刷次**。
  刷次固化是既有语义,撤完出现 1、3 跳号是对的,不要去「修正」它。

老记录没有 `bid`,**永远不出现撤销入口** —— 不回填、不迁移。

草稿(`draft`)、撤销指针(`undo`)、计时(`run`)是同一类东西:**这台设备此刻的临时状态**。
`load()` 要读回来,但**导出不带、导入也不吃别人的**。加同类字段时照这个规矩办。

**达标口径不受影响**:`stateOf()` 只看 `d.min` 是否全部完成,标准线做没做不影响达标判定。
这是用户明确定的默认值,**不要因为加了标准线就改动 `stateOf()`**。

**断档恢复文案**(`justRecovering()`):过去两天(不含今天)都只完成最低线或完全空白时,
标准线区块上方出现一句「这两天量少也没关系,标准线一直都在,今天照常看就行」。
纯粹的滑动窗口判断,不持久化任何状态,不隐藏任何内容,只影响这一句文案要不要出现。
**这个判断刻意排除了「用户还没打开过工具的日子」**,否则新用户装上第一天就会被
「安慰」一句她根本没经历过的低迷 —— 判断条件是 `D.days[k]` 必须真的存在。

### v21:真题训练 Stage 1(本轮新增)

真题记录**不进 d.min/d.std/d.plus 那三档**,走自己的命名空间 `D.mockExam`:

```
D.mockExam.records[]  每次训练一条,保存后不再改动
D.mockExam.metadata   为后续难度系统留的位置,Stage 1 是空的,没有假数据
D.mockExam.run        正在走的计时 {subject,year,scope,start},超过 6 小时判为忘了结束
```

一条 record:`{id,subject,year,scope,attempt,d,mins,score,done,ts}`。
`subject` 是 `en1`/`pol1`,`scope` 见 `MOCK_SUBJECTS`,`d` 是保存那一刻 `refreshDay()`
算出来的学习日键(不是时间戳,统计时不反推),`attempt` 是保存那一刻算出来的数字。
**刷次由系统算**(同科目+同年份+同题型已有几条),她不填;得分可以一直空着。

**统计不另起一套**:`todayMins()` / `subjLastSeen()` / 空壳日判定(`weekFacts`)/
按科目排行,四处都读同一份 `D.mockExam.records`,分类用 `SUBJECTS_BUILTIN` 里
已有的「真题」。一条 record 只贡献一次时长。真题记录不挂在 `D.days` 上,所以
`todayMins()` 和 `weekFacts()` **不能在 `D.days[k]` 不存在时提前 return** ——
从别的设备导入的记录会落在本机没打开过的日子。

`mockFix()` 是 `load()` 和导入**共用**的兜底函数(不是抄两遍,是只有一份规则);
导入按 record 的 `id` 去重,同一份备份导两次不会变成两条。

### v22:真题训练 Stage 2(本轮新增,重点读)

**这一版的主体是「一个字都不用打」。** 用户有 ADHD,障碍是「开始」,要她手填用时和分数
就等于不会填。所以录入只剩两种动作:**点**和**滑**。
`renderMock()` 的录入屏里**不允许出现任何 `type="text"` / `type="number"`**,
r13 有测试直接盯着这条(源码层 + 渲染层各一条)。

**题型清单**(`MOCK_SUBJECTS[sub].sc`):每一项自带四个常量 —— `q` 题目数、`per` 每题分值、
`full` 满分、`mins` 考场建议用时。**有 `q` 就是客观题**(只点错了几题,分数由
`mockScoreOf()` 算),没有 `q` 就是主观题(只拖分数滑块)。这两张表是硬编码常量,
**不是按她的历史推算的**,不要做成自适应。

**历史不迁移**:v21 存的 `scope:"read"`(阅读)和 `"new"`(新题型)不在可选清单里,
但留在 `MOCK_SUBJECTS[sub].old` 里 —— `mockValid()` 认它们(不认就会被当成脏数据丢掉),
`mockScName()` 显示它们的老中文名。新记录只能选新清单。**不要写迁移脚本去改写旧记录。**

**多选**:`mkScopes` 是数组,选几个题型就在录入屏出几组,保存时生成几条独立记录,
每条各自算刷次、各自存自己那一格的用时。**不合成一条,也不把总用时摊派下去** —— 摊派是造假。

**计时**:`D.mockExam.run` 记的是「哪一组在计时」。计时完成**只把分钟数填进那一组的滑块**,
不自己落盘,由「保存」统一写入 —— 这样计时和滑块两条路共存,不会各存各的。

**顶部快捷栏**(`#qnav`):今天 tab 有 3200px 高,三档任务区就占 2300px,真题入口不可能进首屏。
快捷栏只做 `scrollIntoView` 导航,**不折叠、不隐藏、不改任何现有结构**。

标准线做的量必须和最低线、加码梯一样被这四处统计到,否则会出现「明明做了却被当成没碰过」
的假阴性。以后新增任何"第四档"之类的东西,这四处要一起改,别漏。

### DOM 桩已知坑(改 `stub.js` 前必读)

1. `querySelector` 不得按需创建元素
2. `querySelectorAll` **恒返回空数组** —— 任何依赖它查找已渲染元素的代码路径
   (比如 `bindMins()` 绑定 `.mi` 输入框)在这个桩环境下永远测不到,只能做静态断言
   (检查生成的 HTML 里有没有正确的 class / data 属性),不要假装端到端测过了
3. `setInterval` 必须返回真值
4. `textContent` 要能从 `innerHTML` 剥标签;设 `innerHTML` 要清 `_text`
5. **`appendChild` 的内容不在 `innerHTML` 里,读取断言要递归子节点或用 `_children`**
   —— 这条坑至少踩过三次(v16 早晚身体组、v18 节点条、v20 学习统计排行),
   每次都是「读 `_html` 读到空字符串就以为功能坏了」
6. **桩不解析初始 HTML 文件里写死的静态文本**,`_text` 对未经 JS 动态赋值的元素恒为空 ——
   这不是 bug,只是桩的覆盖范围,遇到「元素读出来是空的」先确认是不是这条,别急着当成故障
7. `FileReaderStub` 用于测导入路径,传进去的 file 对象用 `__text` 携带内容,
   走真实的 `$("#impFile").onchange` 入口,不要直接调内部函数

### 已知测试盲区

- **默写列表的渲染路径**:`querySelector` 不按需创建元素,一渲染默写条目就崩
- **`.mi` 分钟输入框的端到端绑定**(`bindMins()`):`querySelectorAll` 恒空,见上
- **`Store.mode === "cloud"` 分支**:没有环境可以触发
- **360px 真机排版**:容器里没有真实浏览器,只能做静态 CSS 分析,量不出精确像素。
  上一轮 v19→v20 交界处,`.medmenu`/`.dtlbox` 已经被真机验证过;
  v20 新增的标准线区块(`.task.std`)复用了最低目标同一套 DOM 结构,
  结构性风险较低但**没有被真机验证过**,如果这轮任务涉及它,建议实测一下
