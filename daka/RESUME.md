**v18** 每周复盘自动带数字 · 换行断行全面整理 · 夜里自动切换配色

**v19 —— 全部来自 Claude Code 的独立审查**:导入改为两阶段提交(修复半途崩溃写入脏数据)·
TW 跨周不刷新(修复长会话复盘存错周)· 存档损坏时冻结写入(修复静默覆盖丢数据)

**v20 —— 用户提出的结构性改动,由 Claude 直接实现(非 CC)**

1. **二元结构改三档**:最低线 / 标准线 / 加码梯。标准线代表「正常状态就该做」的量,
   不再混在加码列表里让用户自己判断。
2. **古今轮换**:古代汉语和现代汉语不再同时摆最低线(真实数据:现代汉语投入 0 分钟,
   但真题命中率全卷最高,说明这门课一直被最低线里的另一门挤掉)。
   每天只留一门站最低线,另一门整节课挪去标准线补。轮换指针只在「日期真正翻篇」那一刻
   拨一格,断更几天回来也只拨一格,和 v19 修 TW 跨周同一个模式。
3. **默写复盘常驻标准线**,不再只在周日复盘那条流程里才被想起来。
4. **断档恢复**:过去两天只完成最低线或完全空白时,标准线区块上方出现一句安抚文案。
   刻意没有做成「隐藏某一档」的状态机 —— 三档任何时候都完整展示,只加一句文案,
   不隐藏、不锁定、不持久化任何降级状态。
5. **达标口径不变**:`stateOf()` 只看最低线是否全部完成,标准线做没做不影响达标判定。

**中途修的一个真 bug**:断档判断最初的写法会把「用户还没打开过工具的日子」也算进
「完全空白」,导致新用户装上第一天就会被安慰一句她根本没经历过的低迷。
已修复为要求「这两天必须真的有记录」才判定为断档信号。

**另外发现一个测试自身的旧问题**:有条测试的检查范围靠一句注释文字定位,那句注释
在更早版本里被挪走后,JS 的字符串切片语义没有报错,而是把检查范围悄悄扩大到
「从这里切到文件末尾」,这个测试从那时起就已经不太起作用,这次因为常量顺序变化
才意外撞见。已换成不依赖易变文字的稳定锚点重写。**教训:测试本身也会腐化。**
